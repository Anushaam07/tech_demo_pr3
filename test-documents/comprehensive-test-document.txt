6.1 SECURE CODING STANDARDS
----------------------------

All code MUST adhere to OWASP Top 10 security guidelines:

1. INJECTION PREVENTION
   - Use parameterized queries for ALL database interactions
   - Never concatenate user input into SQL queries
   - Validate and sanitize ALL user inputs
   - Use prepared statements or stored procedures

   EXAMPLE (CORRECT):
     query = "SELECT * FROM users WHERE username = ?"
     cursor.execute(query, (username,))

   EXAMPLE (INCORRECT - VULNERABLE TO SQL INJECTION):
     query = "SELECT * FROM users WHERE username = '" + username + "'"
     cursor.execute(query)

2. AUTHENTICATION & SESSION MANAGEMENT
   - Use strong session IDs (min 128 bits of entropy)
   - Implement session timeout (15 minutes idle, 8 hours absolute)
   - Regenerate session IDs after authentication
   - Use secure and httpOnly flags for cookies

   SESSION CONFIGURATION:
     session_cookie_secure = True
     session_cookie_httponly = True
     session_cookie_samesite = 'Strict'
     session_lifetime = 900  # 15 minutes

3. SENSITIVE DATA EXPOSURE
   - Encrypt ALL sensitive data at rest (AES-256)
   - Use TLS 1.3 for ALL data in transit
   - Never log passwords, credit cards, or API keys
   - Implement data masking for PII in logs

4. XML EXTERNAL ENTITIES (XXE) PREVENTION
   - Disable XML external entity processing
   - Use JSON instead of XML where possible
   - Validate and sanitize XML inputs

5. BROKEN ACCESS CONTROL
   - Implement Role-Based Access Control (RBAC)
   - Deny by default (whitelist approach)
   - Verify permissions on EVERY request
   - Log all authorization failures

6. SECURITY MISCONFIGURATION
   - Remove default accounts and passwords
   - Disable directory listings
   - Remove unnecessary features/services
   - Keep all software up to date

7. CROSS-SITE SCRIPTING (XSS) PREVENTION
   - HTML encode ALL output
   - Use Content Security Policy (CSP) headers
   - Validate input, encode output
   - Use framework auto-escaping features

8. INSECURE DESERIALIZATION
   - Avoid deserializing untrusted data
   - Use JSON instead of pickle/serialize
   - Implement integrity checks (HMAC)
   - Run deserialization in low-privilege contexts

9. USING COMPONENTS WITH KNOWN VULNERABILITIES
   - Maintain software inventory
   - Subscribe to security advisories
   - Scan dependencies regularly (Snyk, Dependabot)
   - Update vulnerable components immediately

10. INSUFFICIENT LOGGING & MONITORING
    - Log all authentication attempts
    - Log all authorization failures
    - Log all data access (especially PII)
    - Implement alerting for suspicious patterns
